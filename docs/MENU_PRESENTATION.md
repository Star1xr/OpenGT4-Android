# Native menu presentation

This implementation uses the user's disc data and ordinary native rendering
and PCM audio. No PS2 processor or sound-chip runtime is used. Assets and
validation WAV/PNG output stay under ignored build/.

## Text

Text uses original FT01 glyphs and advances, with a provisional one-pixel
inter-character gap and the screen's horizontal skew. Measurement, centering,
shrinking and rendering agree about the gap. The original alpha atlas is sampled
at the final drawable resolution, with adjustable text edge clarity. UI images
have independent smooth, sharp cubic, and nearest filters. FSR only reconstructs
the antialiased 3D scene before the UI is drawn. See TEXT_FORMAT.md for assumptions.

## Actors and page lifecycle

MFadeActor(widget, high, low=0) changes opacity over `period` seconds.
MMoveActor(widget, out_x, out_y) moves between the widget's original position
and its out position. `ratio` is provisionally treated as the fraction of the
remaining distance traversed at 60 Hz, converted to elapsed time. MBlinkActor
alternates opacity every `period`. `out`, `repeat`, warp/start/stop/reset/restart
have native state; direction can change mid-animation without a jump.
MScaleActor currently updates text scale only; general container transforms,
rotation and anchor actors remain incomplete and are logged.

The VM owns actor objects; they mark their target widget and unregister from
the menu's weak list during collection. Only the active page advances. The
frontend supplies elapsed seconds and clamps a stalled frame to 100 ms.
Repeat fades currently use a linear ping-pong envelope. These curves and the
exact original reset semantics need reference matching.

The page's `enter(context)` callback runs after initialization and when a page
or cached project resumes. This restores the logo and scroller after returning
from the Arcade submenu. Numeric sync waits from zero to two seconds can
present frames via a frontend callback; they do not re-enter the script VM or
implement coroutines. The frontend pumps quit events while waiting. Longer or
non-numeric waits and transition actors are not implemented. Horizontal SelectBox/ListBox strips display neighbours and move toward the
selected card using elapsed-time exponential easing (18/second). Focus remains
responsive during movement. Exact authored scrolling curves remain pending.

## Button effects

GTSE names in `/sound/gt4se.inf` resolve to Se sequences in `/sound/gt4sys.ins`.
The supported system bank has a Jam header at 0x20, relative u16 sequence and
program tables, and embedded A0 note events followed by a big-endian VLQ delay.
Its FF program provides one split per note. Each split points into the sample
bank, using **8-byte units for this Se bank**, checked against all 18 starts and
the bank boundary. The music bank below uses 16-byte units instead.

Sony ADPCM blocks are decoded into PCM once per requested effect. Notes are
mixed into a bounded stereo buffer with pitch, split/program volume and pan;
SDL copies that buffer into one of 16 asynchronous voices. Changing focus
plays `cursor`; activation/cancel sounds come from the game's script calls.
The system bank's 11 simple sequences render successfully. `oil` uses pitch
controllers not implemented yet and is rejected, not interpreted as noise.
Other effect banks are not supported yet. The 240 Hz delay-clock assumption
is provisional; noise and reverb are pending (the menu effects' ADSR is an
instant attack with full sustain and no note-off, so it changes nothing).

Pitch (2026-09-29): effects use the music banks' tone rule, 44.1 kHz samples
transposed by (note - split root + fine/16) semitones. Every system effect's
root lies near its note (cursor 49/48, select 41/42, param 36/46); the former
root-minus-C4 rule played cursor at 0.5x (over an octave low, 63 ms instead
of 32 ms). Navigation sound choice, from CORE: a RootWindow's
`navigate_sound` defaults to `cursor` (constructor 0x00232E00) and is played
by its focus move (0x002359B0) and by ListBox (0x002DAB50); SelectBox's own
key handler (0x002D6F58) plays none. Pages may override it (`select`,
`license_cursor`); menu.c now uses the page's value. Our SelectBox still
plays it on each move and wraps at the ends; the original's SelectBox
stops at the ends (0x002D7468/0x002D7528) and its own sound path is not
fully traced.

## Arcade music

The native sample sequencer reads `/music/us/arcade.ins` and `arcade.sqt`.
INST's Jam program table describes note ranges, root pitch, fine tuning,
volume, pan and sample offsets. Music sample offsets use 16-byte units;
FF-filled unused splits are skipped. Samples are decoded at load time, with
ADPCM loop flags retained.

Ssqt contains a table of Sssq sequences; the current player opens sequence 0.
The Sssq stream has a PPQN field and MIDI-like delta events with running status.
Note-off and pitch bend each have one data byte here. The parser reads tempo,
note on/off, program, volume, expression, pan, sustain and pitch bend. Controller
99 values 20/30 establish the song loop. Events are converted to sample times
before playback. A producer thread synthesizes up to 64 voices ahead into a
16384-frame ring, targeting 8192 queued frames (171 ms at 48 kHz). The device
callback only consumes PCM and mixes effects; it does not run the sequencer. The Arcade track starts on Arcade subpages; the top menu is silent. Other project music/playlists are pending.

This is audible native music, not yet an exact reconstruction: attack/release
now follows the stored ADSR fields; pitch-bend range is two semitones, master mix gain
is a port setting, and LFO and reverb are not reconstructed. These choices
are explicit approximations, not measurements of the original game's output.
There has not yet been a listening comparison against a PS2/PCSX2 recording.

## Validation

CTest covers synthetic font spacing, actor timing/reversal/stop/warp/GC,
ADPCM samples and malformed blocks, SQT/INST truncation, and a repeating song
with synthetic instruments. Existing navigation and format tests also pass.

Optional real-disc validation, output directory must already exist:

```
build/Release/sound_tests.exe <disc.iso> build/audio_check
python tests/ui/run_menu_smoke.py <disc.iso>
```

The audio test renders 11 named effects plus a 12-second Arcade music excerpt,
checks nonzero PCM and bounds, and saves local WAVs. This verifies decoding and
synthesis, not audible fidelity or the user's speaker configuration. The seven
navigation scenarios capture menus after animation settling. Normal playback
uses the same decoder and synthesizer through SDL's stereo 48 kHz backend.

Format research (reference only; implementation is original C):
- [Nenkai GT4SoundTool structures](https://github.com/Nenkai/GT4SoundTool)
- [INST/Jam template](https://github.com/Nenkai/GT-File-Specifications-Documentation/blob/master/Formats/PS2/GT4/GT4_INST_SShd_Jam_Custom.bt)

Differences from the unfinished research tool, including the system bank's
8-byte offsets, were checked against the user's local files.

## Timing and presentation fixes

Script watchers advance at 60 ticks per real second, independently of display
refresh. Animation and script sync waits share a presentation clock to avoid
counting elapsed waits twice. Tests cover 30/60/120/144 Hz. A dummy audio device
runs for two seconds with injected 60 ms producer stalls and checks zero
underruns. This is not a listening comparison on the user's speakers.
SQT timing is also checked with a 480-tick note at 500000 us/quarter, which must
start at sample 24000. The actual Arcade track changes to 480000 us/quarter
(125 BPM) at 0.3 s. No arbitrary global tempo reduction is applied. ADPCM
terminal flag 7 no longer overwrites the sample loop start.

Closed OptionMenu fields render only the indexed value, with state-dependent
backgrounds. setIndex(context,index) initializes that value. Race settings use
provisional defaults (AT, Normal, map on, steering off); save persistence and
the expanded dropdown remain unfinished; closed fields accept keyboard changes. FrameImageFace draws all nine
slices using declared border sizes. Race Settings was inspected in a fresh
native screenshot after correcting the font, dropdown overlap and frame fill.

## Follow-up: audible timing complaint

A real WASAPI device test produced 389632 frames in 8.004 s (including ahead
buffer), with no underruns despite injected 60 ms stalls. This rules out a
1.5x-2x device consumption rate in that test; it does not establish musical
fidelity. Run `audio_backend_tests --real` to repeat silently.

The frontend now keeps TopRoot silent and starts Arcade music on entering
Arcade subpages, stopping it on return or project change. The sequence is
prepared as 48 kHz PCM before playback (about 24 MB for Arcade) so live
synthesis cannot stall it. Overlapping instrument splits are retained as
layers instead of overwriting one another. Looped samples continue through
the release envelope, rather than cutting out at the next sample boundary.
Exact ADSR/LFO/reverb and comparison with the original remain pending.

`--music-tempo` is retained as a speed override, but now scales both sample
playback and sequence events. It also changes pitch; pitch-preserving stretching
is not implemented. Default is 1.0 (authored sequence timing). The previous
0.667 event-only slowdown was removed because prerecorded rhythm phrases
finished while the sequencer was still waiting for the next bar.

## Instrument envelope follow-up

The user located the held-note artifact near 5 seconds of the 0.667 comparison.
The native synth previously ignored both ADSR words, using a fixed 5 ms attack,
no decay, constant sustain and an 80 ms release for every instrument. It now
uses the bank's attack/decay/sustain/release fields for a per-voice amplitude
curve at 48 kHz. Pitch and sequence tempo are separate from this envelope.
Interpolation at a sample-loop boundary now interpolates toward the loop start.
Synthetic tests verify that fast release silences the loop and that decreasing
sustain can finish before note-off. These checks do not establish that the
reported audible artifact is fully resolved; the new same-tempo listening
sample is build/audio_envelope_check/arcade_music.wav.

Format/behavior references (independent native implementation):
- https://psx-spx.consoledev.net/psx-spx.pdf (volume/envelope fields)
- https://github.com/PCSX2/pcsx2/blob/master/pcsx2/SPU2/ADSR.cpp (SPU2 envelope semantics)
The native envelope uses interval-based updates; exact hardware edge cases,
LFO and reverb remain outside this implementation.

## Source sample clock and rhythmic gaps

INST sample roots now use 44100 Hz source PCM, converted into the 48000 Hz
output mix. The output device itself stays at 48 kHz. This corrects the rate
of the actual sample contents without changing authored SQT event times.

Evidence from Arcade program 0, note 60: 61488 decoded samples and pitch ratio
0.72782659 occupied 1.7600 seconds under the old 48 kHz source assumption.
At 44.1 kHz they occupy 1.9157 seconds, matching the 1.9200-second SQT bar to
within 4.3 ms. Program 1 independently measures 1.9225 seconds at 44.1 kHz.
The prior event-only 0.667 setting stretched the bar to 2.8786 seconds while
leaving the rhythm sample at 1.7600 seconds: more than one second of missing
rhythm at each repetition. This was a synthesis/timing mismatch, not a measured
Windows output-device underrun. It explains a concrete gap in the comparison
near 5 seconds, but listening comparison with original playback is still needed
for overall musical fidelity.

A synthetic 44100-sample one-shot test checks that audio is present at 0.99 s
and absent just after 1 s; at half speed both the sample and sequence scale
together. This test would fail with the former source-rate assumption. New
real-disc output: build/audio_rate_fixed/arcade_music.wav. Earlier comparison
files remain unchanged for auditing. The sampled root rate is also consistent
with GT4SoundTool's instrument-to-SF2 export (reference, no code copied):
https://github.com/Nenkai/GT4SoundTool/blob/master/GT4SoundTool/Program.cs

## Loading and continuity

Arcade music preparation runs on its own worker/volume cursor from startup.
The menu remains usable until PCM is ready; playback still starts only on
Arcade pages. Attaching/detaching music now retains the SDL device and sound
voices, avoiding the device close/reopen pause. Accepted source rate, tempo,
synthesis and buffered playback are unchanged.
Movie and 3D loaders are independent, bounded and discard outdated selection
results. A car change hides the previous car at once (it could be another
maker's) and shows the empty studio until the requested model is loaded;
the car then fades in over 0.4 s (our length; the original's subtle load was
only observed in PCSX2), also on each entry to CarRoot. A failed load shows
no car rather than a wrong one. See MOVIES.md and
MODELS.md. These changes remove synchronous heavy asset work from navigation;
they are not a claim of pixel-exact original animations or universal 60 fps.

  travel, animating the original category arc images around their pane centre.

  Cursor placement is currently derived from the focused widget/card; the full
  cursor script's alignment and motion are still pending.

  Thumb width reflects the visible fraction; it stays within the authored bar.
  The provisional gold position badge was removed.
- Car miniatures honour the selected magnify ratio; only the selected item
  displays its conditional arrow. The paint help appears only in paint mode.

## Page transitions

The menu context starts with an `MColorTransition` (period 0.25 s, constructor
`00286EA0`; setter `002874F0`). Its period applies to each transition leg. The
arcade scripts never assign `context.transition`, yet `_start_page` calls
`transition.panOutIn` when one is set, and PCSX2 fades through black on
those page changes (course list, maker list, maker <-> showroom). So the
native context must provide one by default; GT Mode assigns its own.
`pushPage` (TopRoot -> GameRoot) has no transition in the script.

## CarRoot: paint chips and driving options

Accepting a car runs the script's own `set_col_select`: it copies
`StoreHouse::ColItem` once per paint (`car_data.getColors()`), calls
`chip.setData(car_data, i)` and appends it to `ColScroll::SelectBox`;
moving calls `set_col` -> `CarFace.setColorIndex` and `getColorName`.
The paints are the VARIATION rows of the car's model in order (+4), name
(+12) and chip colour (+36: r, g, b in GS scale, then 3 metallic / 1
solid). `ColorChipFace` fills its rect with the colour and draws
`image_path0` (metallic) or `image_path1` (solid), a white sheen with low
alpha, on top. Accepting a paint opens `SettingPopup` (pushPage); its OK
runs `doGame`, whose `finish` with sequence single_race / time_trial starts
the race view on the chosen course, car and paint.

A horizontal card strip keeps the focused card centred only when the cards
overflow the box; when all fit, the row stays centred (PCSX2: a maker's
five cars, the paint chips).

## Text sharpness

The FT01 glyphs are bitmaps for a 640x480 screen (hm_16's letters are about
12 texels tall, and no larger face of that family is on the disc). Each
glyph atlas is turned into a distance field when the font loads
(src/core/glyph_sdf.c): up to 4x the atlas, the coverage resampled with a
Mitchell-Netravali cubic (the traced edge follows the letter's curves, not
its texel steps), cut at 0.5 and passed through an exact distance
transform. The texture keeps the disc's bilinear coverage in r and the
signed distance in a. The glyph shader (video_gl.c) draws the coverage at
Text Clarity 0 (the disc's soft look) and, above it, cuts the distance at
0.5 with a transition measured on screen: about 2 px at 50, under 1 px at
100, at any window size.


## Cursor popup actors and colour fade audit (2026-09-30)

Common dialogs now run the original cursor.adc motion: panel entry Y=480,
move ratio .2 times context.cursor_speed_ratio, root fade period .5 divided
